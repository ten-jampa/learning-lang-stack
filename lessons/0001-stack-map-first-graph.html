Lesson 0001 — The stack in one map + your first graph

One thing: say which layer owns your problem, then run a graph with no API key. ~20 min. No prior LangChain knowledge assumed; plain Python is enough.

1. The map: three layers, each in plain English

An agent is just a program that calls a model, uses the result (often by calling a tool — a plain Python function the model is allowed to invoke, e.g. "look up the weather"), and repeats until done. That repeat-until-done cycle is the loop. The three layers split two jobs: who defines the loop vs who runs it reliably.

LangChain — the framework. Ready-made pieces: connections to models (OpenAI, Anthropic, …), ready-made tools, and create_agent — a pre-built loop (model → tool → model → …) you can use without designing anything. Note its limits: the standard loop only — no bundled planning step, no subagents, no filesystem. Use it when that standard loop is all you need. [LangChain agents]
LangGraph — the runtime. Lets you design your own loop as a graph of steps, and runs it reliably: it can pause for human approval, save progress so a crash resumes where it stopped (checkpointing), and stream intermediate results. The price: you hand-build the wiring yourself. Use it when the shape of the loop is itself your spec — branches, approvals, multiple actors, long runs. [LangGraph overview]
Deep Agents — the opinionated harness. A ready-made long-horizon agent built on the other two: it plans, delegates to helper agents (subagents — agents with their own isolated context, so the main one doesn't drown in detail), reads/writes files, and summarizes long histories. Use it for research/coding tasks where you want all that bundled. [Deep Agents README]

(A fourth name you'll see, LangSmith, is the observability platform — tracing, evaluation, deployment. It watches your agent run; it doesn't define or execute the loop. Full story in a later lesson.)

Memory hook: the harness owns the loop, the runtime owns the execution. Standard loop → take a harness. Custom loop shape → drop to the runtime. (They compose: any finished graph can be plugged in as a Deep Agent subagent — later lesson.)

Full cheat sheet: reference/stack-map.html

2. Five words before any code

A LangGraph program has exactly five moving parts. Read these slowly — every line of code below is one of them:

1. State — a shared dictionary every step can read and update. Think of it as the notepad passed around the team. MessagesState is a ready-made notepad whose only page is "messages", a list of chat messages.
2. Node — one step of work: a plain Python function fn(state) → update. It reads the notepad and returns only what's new; LangGraph merges it in.
3. Edge — wiring: "after X, run Y". START and END are fake markers meaning "the beginning" and "finished", so add_edge(START, "llm") reads as "first, run the llm step".
4. compile() — freezes your wiring into a runnable app. Before compiling you have a drawing of the workflow; after, an executable.
5. invoke() — runs the app once: you hand it the starting state, it walks the wiring to END, and hands back the final notepad.

3. Build it, line by line (explicit steps)

Do exactly this. The "LLM" is a stub returning a fixed string, so no API key is needed — you're learning the shape first, real models in lesson 2.

Step 1. Open a terminal and go to the repo root (this folder, the one containing .venv). Confirm with ls .venv — you should see bin listed. All commands below run from there.
Step 2. Copy-paste this whole block into your terminal and press enter. Expected output on the last line: hello world. 
.venv/bin/python -c "
from langgraph.graph import StateGraph, MessagesState, START, END
def mock_llm(state: MessagesState):
    return {'messages': [{'role': 'ai', 'content': 'hello world'}]}
g = StateGraph(MessagesState)
g.add_node('llm', mock_llm)
g.add_edge(START, 'llm')
g.add_edge('llm', END)
out = g.compile().invoke({'messages': [{'role': 'user', 'content': 'hi'}]})
print(out['messages'][-1].content)
"
# expect: hello world
Step 3. If you see hello world, it worked. If you see No such file or directory: .venv/bin/python, you're in the wrong folder — cd to the repo root and retry. Any other error: paste it to me and we'll debug together.

Now map each line back to the five words:

  • StateGraph(MessagesState) — "my notepad is a message list."
  • def mock_llm(state): return {'messages': [...]} — a node: reads the notepad (ignores it here), returns one new AI message. Note it returns only the update, not the whole state.
  • add_node('llm', mock_llm) — registers the function under the name "llm" so edges can point at it.
  • add_edge(START, 'llm') / add_edge('llm', END) — the full wiring: begin → llm → finished.
  • compile() — drawing becomes executable. invoke({...}) — run once with a starting user message; out is the final notepad, and out['messages'][-1] is our AI message.
Tangible win: you can now narrate what each of the five lines does. That five-step shape — state → node → edge → compile → invoke — is every LangGraph program you'll ever write.
