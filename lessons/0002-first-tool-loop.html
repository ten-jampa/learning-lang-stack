Lesson 0002 — Your first tool-loop with create_agent

One thing: give an agent exactly one ability (a weather tool) and watch the model → tool → model loop run. ~20 min. Needs the API key you put in .env (lesson 1 needed none; from here on, real model calls). Assumes lesson 1's five words (state, node, edge, compile, invoke).

1. Four new words, then code

1. Tool — a plain Python function the agent is allowed to call, e.g. get_weather(city). The function's docstring is the tool's user manual: it's what the model reads to decide when to call it and what arguments to pass. No docstring = the model is guessing blind.
2. Tool call — the model's structured request: "call get_weather with city='sf'". Crucial detail: the model never runs your function. It only asks; the harness executes the function locally and pastes the result back into the conversation.
3. The loop — create_agent's whole job: send messages to the model → if the model requests a tool call, run it and append the result → repeat until the model answers directly. You never write this loop; the harness owns it (lesson 1's hook).
4. System prompt — standing instructions prepended to every run ("You are a helpful assistant"). It shapes behavior; it does not grant abilities — only tools=[...] does that.

The punchline for your mission: an agent's tools are its boundary. Whatever isn't in tools=[...], the agent cannot touch — files, shell, network, nothing. Scoping a spec starts with scoping that list. [LangChain agents]

2. Build it, line by line

Step 1. Terminal, repo root (folder containing .venv and .env). Confirm keys load: .venv/bin/python -c "from dotenv import load_dotenv; import os; load_dotenv(); print(bool(os.getenv('ANTHROPIC_API_KEY')))" → expect True. If False, your .env is missing or malformed — fix that first.
Step 2. Paste this block. One real model call on claude-haiku-5-5 (our fast/cheap default — fractions of a cent), ~10–30 s: 
.venv/bin/python -c "
from dotenv import load_dotenv
load_dotenv()
from langchain.agents import create_agent
def get_weather(city: str) -> str:
    '''Get weather for a given city.'''
    return f\"It's always sunny in {city}!\"
agent = create_agent(
    model='claude-haiku-5-5',
    tools=[get_weather],
    system_prompt='You are a helpful assistant',
)
out = agent.invoke({'messages': [{'role': 'user', 'content': 'what is the weather in sf'}]})
print(out['messages'][-1].content)
"
# expect: a sunny-San-Francisco answer in the model's own words
Step 3. Errors? AuthenticationError → key wrong/missing in .env. ModuleNotFoundError → wrong folder or venv. Anything else → paste it to me. (OpenAI instead? Swap the model string to 'gpt-4o' — same shape, different provider.)

Map each line back to the four words:

  • def get_weather... — the tool. The logic is a stub (always sunny) so you can see the loop without depending on a real API. The docstring is its manual.
  • create_agent(model=..., tools=[get_weather], system_prompt=...) — "here's the model, here's the one thing it's allowed to touch, here's its standing instructions." Returns a compiled, runnable app — yes, the same CompiledStateGraph species as lesson 1. The harness is a graph under the hood.
  • invoke({'messages': [...]}) — identical shape to lesson 1: starting notepad in, final notepad out. Inside, the loop ran: model asked for get_weather('sf') → harness ran your function → model turned "It's always sunny in sf!" into a friendly answer.
Tangible win: you scoped an agent's entire boundary in one list (tools=[...]) and ran a real model through the loop. Everything from here — more tools, memory, approvals — is elaboration on this shape.
